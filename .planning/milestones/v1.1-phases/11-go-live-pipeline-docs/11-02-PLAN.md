  <action>
Write a concise, accurate guide documenting the seven drop-in steps for adding a new in-site companion
app. Ground every step in the real files (read them first — do not invent APIs). The steps, per the
FIXED APP-05 decision:

1. Add the app component under `src/components/armory/` (one .tsx file). Scope all of its own CSS under
   a unique wrapper class so nothing leaks into the shared Nocturne shell — cite Fate of the Fellowship's
   `.ff` wrapper as the reference.
2. If the app needs dependencies or Tailwind, follow the Burning Banners scoped skip-preflight pattern:
   a per-app stylesheet that imports only the tailwindcss theme + utilities layers (never preflight),
   with `@source` pointed at that one component, imported ONLY from the component; import icons by name
   (no barrel import). Cite `src/styles/armory-bb-tailwind.css`.
3. Migrate any storage shim to real `localStorage`, with all reads/writes inside `useEffect` (SSR-safe —
   a build-time read breaks `astro build` outright), namespaced per app.
4. Register ONE entry in `src/lib/armoryApps.ts` (slug, name, title, description, Component).
5. Add ONE static import + ONE `DISPATCHED_SLUGS` entry + ONE `client:only="react"` dispatch line in
   `src/pages/armory/[slug].astro`. Note the build-time parity guard enforces the dispatch line exists.
6. Add ONE record to `src/data/catalog/tools.ts` with `kind:"internal"` and slug matching the registry
   exactly (status:"live" when ready to ship). Warn that the slug must match verbatim across registry,
   route dispatch, and tool record, or the Launch link points at a dead route.
7. Run `npm run build` (not just `astro dev`) — it is the acceptance gate that catches the SSR/localStorage
   and CSS-leak classes of error that dev mode hides.

Include a short "two worked examples" framing: FOTF = the clean, zero-new-dependency reference case;
Burning Banners = the heavier deps + scoped-Tailwind case. Keep it tight and skimmable (headings +
numbered steps + the two example callouts). Match the existing docs/ prose style.

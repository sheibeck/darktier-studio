<objective>
Add an optional, additive `Tool.kind?: "external" | "internal"` field so the Armory's data model, admin CMS, and public `/tools` listing can distinguish in-site (internal-route) apps from external links — with zero regression to every existing tool record.

Purpose: This is the foundational, backward-compatible data-model change the rest of milestone v1.1 depends on (Phases 9-11 wire the actual `/armory/<slug>` app routes). It lands and ships standalone with no visible behavior change to any existing tool.

Output: `Tool.kind` field on the shared type; a same-tab-vs-new-tab Launch branch in `ToolsLive`; a "Link type" select in the admin tools editor. No new dependencies, no Firestore rules change, no SSR adapter — the site stays fully static on the free Spark plan.
</objective>

<threat_model>
Security posture: ASVS L1. This phase adds only an owner-controlled enum field (`kind`, a two-option select) behind the existing owner-UID-gated Firestore writes. It introduces NO new untrusted input, NO new public surface, and installs NO packages (no supply-chain / `T-08-SC` row applies). Block-on-high applies; no high threats are expected. Existing rules are not weakened.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner (authenticated) → Firestore `tools/{slug}` write | Only the hardcoded owner UID may write; `kind` is one more owner-set field on that already-trusted path |
| Public visitor → Firestore read (`hidden == false`) → `ToolsLive` render | Untrusted readers see only non-hidden docs; the new `kind` field is rendered, never executed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `ToolsLive.tsx` render of `t.kind` | low | mitigate | Branch on strict `t.kind === "internal"`; any other/garbage/absent value falls through to external behavior with no throw — a malformed `kind` cannot break the render |
| T-08-02 | Injection | `ToolsLive.tsx` derived `href={/armory/${t.slug}}` | low | mitigate | href is a same-origin path (always prefixed `/armory/`, never `javascript:`); slug is produced by the existing `slugify()` (lowercased, `[^\w\s-]` stripped) and written only by the owner; React escapes the attribute value |
| T-08-03 | Info Disclosure | Reverse tabnabbing on Launch anchor | low | mitigate | Internal links omit `target` entirely (same-tab, no `window.opener`); external links retain `target="_blank" rel="noopener"` — no regression to existing external behavior |
| T-08-04 | Elevation of Privilege | Firestore write authorization for `kind` | low | accept | `firestore.rules` gates all `tools` writes to the owner UID and is intentionally UNCHANGED; no per-field schema validation is added; `npm run test:rules` re-confirms the gate still holds |
</threat_model>

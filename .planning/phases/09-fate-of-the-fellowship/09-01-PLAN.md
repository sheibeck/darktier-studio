  (A) Persistence — migrate the artifact storage shim to real browser localStorage. The app was authored as a Claude-artifact and currently reads/writes through `window.storage` (an async KV shim that does not exist in a real browser, so persistence silently no-ops today). In the load effect, replace the `await window.storage.get(STORE_KEY)` call (which returned an object whose `.value` held the JSON string) with a synchronous read of the value stored under STORE_KEY from the browser's localStorage, then `JSON.parse` that string; keep the existing try/catch and the `setReady(true)` in the finally so first render always uses static defaults and restore happens post-mount. In the debounced save effect, replace the `window.storage.set(STORE_KEY, json)` call with a write of the same JSON string to localStorage under STORE_KEY, wrapped in try/catch (private-mode/quota safety) so a failed write never throws. Keep the storage key exactly `fotf:v2` (the STORE_KEY constant) and the serialized object shape (tab, players, diff, hope, threat, drawn, turn, active, phase, idx, checks) unchanged so any latent saves round-trip. The app's existing reset path (the "new game" callback that resets state to defaults; the save effect then persists those defaults) is the explicit reset — do not remove or alter it. Both effects already run only after mount, satisfying APP-03's "all localStorage access post-mount." Do NOT read localStorage at module top level: the registry in Task 3 imports this module at build time in Node (no window/localStorage), so any top-level browser-API access would throw during `astro build` — keep every localStorage reference inside the effects.
  <!-- planner-discipline-allow: window.storage -->

  (B) CSS scoping — scope EVERY selector in the `const CSS` template string under the app's `.ff` wrapper. Today only four rule groups are scoped (`.ff`, the `.ff *` reset group, `.ff button`, `.ff :focus-visible`); every other top-level rule uses a bare selector (for example the app's own `.nav`, `.btn`, `.card`, `.status`, `.pad`, and the ambient `.amb`, plus the previously-unscoped `.body` rule near the middle of the block) and would leak document-wide the moment the app renders inside Layout.astro next to the Nocturne Nav/Footer — the app's `.nav` and `.btn` in particular collide with Nocturne's own nav and button classes on the same page. Rewrite the string so each top-level rule selector becomes a descendant of the wrapper (prefix it with the wrapper class + a space), turning each bare class rule into a `.ff`-scoped rule and the descendant/element rules (things like the accordion `p`/`ul`/`li`, table cells, `.face` children, comma groups such as the two `.ends` colour rules) into `.ff`-scoped descendants too. Handle lines that pack multiple rules and comma-separated selector groups. Leave the four already-scoped groups unchanged, leave the leading `@import` font rule and the `@media (prefers-reduced-motion)` at-rule as at-rules (the selector inside the media block is already `.ff *`), and leave every declaration/value/pseudo-element untouched. The mount point is already `<div className="ff">` wrapping `<style>{CSS}</style>` and the app tree, so `.ff`-prefixed selectors will match. Result: no selector from this block can match anything outside the app's own subtree.

| Nocturne shell ↔ app island | the app's injected `<style>` block shares the document with Nav/Footer; unscoped selectors cross this boundary |
